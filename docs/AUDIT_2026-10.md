# Audit, redesign and roadmap — October 2026

Scope: review of the strategy stack, application runtime and interface at commit `6617dd4`
plus the changes made on branch `arena/f3471b2a-trading-command-v3`.
This is a code and UX audit, **not** a profitability claim, a security certification, or a
statement that live execution is safe to enable.

## 1. Method

1. Read the strategy modules (`src/lib/strategy/engine.ts`, `src/lib/strategy/v2/*`), market
   facade (`src/lib/market/*`), accounting (`src/lib/account.ts`), risk (`src/lib/risk.ts`),
   paper engine and the API routes that compose them.
2. Ran the repository's own gates: `npm run typecheck`, `npm run lint`, `npm run build`,
   the quant/exchange/gateway suites, the paper-trading end-to-end test and the
   CoinDCX-boundary test.
3. Ran an independent compiler pass with `--noUnusedLocals --noUnusedParameters` to find
   dead code that the project's own settings did not report.
4. Drove the running application with a headless browser across all 12 routes at 1440×1000
   and 390×844, recording console errors, page exceptions, horizontal overflow and
   undersized tap targets.
5. Benchmarked the interface against three widely used trading products and their own
   documentation (TradingView Supercharts, Coinbase Advanced, Kraken Pro).

## 2. Strategy findings and fixes

| # | Finding | Why it mattered | Fix |
|---|---|---|---|
| S1 | Donchian ribbon compared each close against a window that **included the current candle** (`i - period + 1 … i`) | A candle can never close above its own high / below its own low, so `green`/`red` trend states were heavily biased and the trend carried forward from an arbitrary `"green"` seed instead of a neutral state | Window is now `i - period … i - 1` (prior highs/lows only), the carry-forward seed is `"neutral"`, and the type is `"green" \| "red" \| "neutral"` |
| S2 | Chandelier Exit seeded its stops from the very first candle at index 0 while ATR was `NaN` through warmup | Early stops were computed from a partial ATR and could produce `NaN` trailing levels that silently became signal values | Warmup bars are skipped, stops are derived from the trailing `atrLength` window, and crossover checks use the **previous** bar's stop so a level known in advance is what gets crossed |
| S3 | Backtester evaluated signals on `candles.slice(0, i + 1)` | The signal for bar `i` was computed with bar `i` included, so the entry looked like it knew the current bar — look-ahead bias | Signals are evaluated on `slice(0, i)`; entry fills at the next real candle **open**; the current bar can only trigger a stop or a time-stop |
| S4 | Fills and stops were taken from **Heikin-Ashi** levels (a synthetic series) | HA closes/highs/lows are averages that never traded; fills and stops were unmatchable prices | Execution uses raw candle open/high/low; HA is only an indicator input. The strategy signal now reports the executable market close as `entry`/`price` |
| S5 | Trailing-stop exits used a stop recomputed from the current bar | Same-bar stop moves could exit at a level that did not exist when the bar opened | Exits use the previous bar's trailing level; a gap through the stop fills at the worse opening price |
| S6 | `calculatePositionSize` returned a negative risk amount when the stop sat above the entry (and reported "risk" that ignored the margin cap) | Sizing silently produced nonsense numbers in long/short edge cases | Invalid geometry returns a zeroed, explained result; the returned `riskAmount`/`riskPct` now describe the size actually returned |
| S7 | Manual lot size was rounded through a fixed 4-decimal path | Rounding up could exceed the risk or margin budget | Quantities are floored to the exchange-compatible step |
| S8 | Backtest Sharpe was annualized with `sqrt(252 × 288)` on **per-trade** percentage returns, then clamped to `[-1, 1]`; "DSR" was computed with a placeholder trial count | Both numbers looked like standard statistics while measuring nothing comparable; the clamp also hid large values | The ratio is reported as **return per unit of trade volatility** (no annualization, no clamp) and DSR is reported as `null` with the reason shown in the UI |
| S9 | Profit factor was `0` when there were no losing trades | A perfect sample displayed the worst possible value | Reported as `null` → "N/A (no losses)" |
| S10 | Walk-forward loop stopped one window early, re-ran the whole history each step, and `aggregateWalkForward` compounded independent windows into one curve; `step` was unvalidated | Fabricated equity curve, truncated sample, and a `step = 0` infinite loop | Exact final window is included, windows are rejected unless `step ≥ testWindow`, and aggregation reports trades with the **worst window drawdown** instead of an invented compounded curve |
| S11 | Sizing in the API assumed a fixed `$10,000` equity | Every estimate was wrong for any other account | Sizing uses the real account state, is only produced when that equity is verifiable, and is refused for live mode with an explanation |
| S12 | The breakout strategy classified levels against the current price and then tested the same price against them | A close above resistance reclassified the level as support, so the breakout branch could not fire — a dead strategy path | Classification uses the **previous** close and the levels list computed from candles *before* the last one |
| S13 | The signal API evaluated the still-forming candle | Unclosed candles made the reported status flicker and repaint | Only fully closed candles reach the evaluator |
| S14 | `BACKTEST` used a `trades.length < initialCapital * 10` loop guard and unbounded indicator periods from settings | Non-numeric or absurd settings could throw inside a request or hang the process | Configuration is validated once (`validateStrategyConfig`, also enforced in `POST /api/settings`), and the guard was removed in favour of the closed-bar loop |

Two behaviour changes are intentional and visible: signals may now report `WAIT` where they
previously reported a setup, and the strategy lab's ratio statistic is no longer labelled
"Sharpe".

## 3. Application and runtime fixes

| # | Finding | Fix |
|---|---|---|
| A1 | `dataSource` could only ever be `"live"`: the market facade ignored the setting and always called CoinDCX, so onboarding's "demo mode" was a lie and an unconfigured install produced a dead workspace | The facade routes to the deterministic simulator when the setting is `demo`, and `dataSource` accepts `demo \| live` end to end. There is still **no** silent fallback from failed live data to demo data |
| A2 | Onboarding wrote `dataSource: "demo"`, but the settings UI offered no way back to it | Explicit "Demo simulator / CoinDCX Futures" selector in Settings → Market data |
| A3 | `usePoll` never cleared the previous resource when the subscription changed, so switching symbol or timeframe kept showing the **old** payload until the new request resolved | Data, error and loading state are reset on a key change; a `refresh()` result is now stable across renders and a slow response cannot overwrite a newer one |
| A4 | The strategy panel kept its own `useState(DEFAULT_CONFIG)` copy separate from `settings.chandelierDonchian` | One source of truth: the panel renders `settings.chandelierDonchian` |
| A5 | Nested `<a>` elements from an earlier search-and-replace produced duplicated nav links | Navigation uses `<Link>` consistently |
| A6 | `useApp.getState().activeSymbol` inside a `useMemo` did not re-run when the symbol changed | Proper dependency, so the ticker poll target updates |
| A7 | Paper risk checks were skipped in practice: `placePaperOrder` received no equity/max-leverage context, so the leverage limit never activated | Equity is computed from starting balance + realised + open P&L and passed through, activating the shared `evaluateOrderRisk` leverage gate |
| A8 | `evaluateOrderRisk` allowed an order when equity was `0`/`NaN` and when exposure was non-finite; `normalizeRiskLimits` could round a fractional position count down to **unlimited** | Both fail closed and the position limit is floored at 1 |
| A9 | History grew without bound (seen-signal sets, signal list) and every `LONG_SETUP` re-notified | Sets are capped, hydration is skipped, and notifications require an enabled matching rule |
| A10 | An `AudioContext` was created per alert and never closed | Closed on `onended` |
| A11 | Table rows used a sticky-header class that did not apply to their own `<thead>` | Removed in favour of the styles that actually apply |

## 4. Dead code and lint debt removed

Found by the stricter compiler pass and removed without changing behaviour:

- 6 unused repository insert types in `src/lib/repo/file.ts`, unused `flags` import in
  `src/lib/account.ts`, unused exports in `src/lib/flags.ts` and unused test imports.
- Unused icon/type/state imports in `AppShell`, `ChartPanel`, `CommandPalette`, `settings`,
  `strategy`, `markets`, `ChandelierDonchianConfig` and the strategy page.
- `ChartPanel`: unused `bgColor`, and `startPx/startPy` parameters that were declared but
  never used (the drag origin is now read from them, which also fixes imprecise drags when a
  chart is scrolled or zoomed).
- The duplicated 231-line Chandelier/Donchian page: the page now renders the shared
  `ChandelierDonchianPanel` and chart instead of a second copy of the same logic
  (`-801 / +406` lines overall, ~400 net lines deleted).
- The settings default `chandelierDonchian` block was duplicated in two modules with
  identical literal values; server defaults now re-export the single canonical object from
  `src/lib/strategy/v2/types.ts`.
- `noUnusedLocals` / `noUnusedParameters` are now enabled in `tsconfig.json`, so this class
  of debt fails the build instead of accumulating.
- Two unused icon imports were removed, and `src/lib/strategy/quant/quant.test.ts` no longer
  imports unused modules (its golden assertions were untouched).

Not removed, deliberately: the retired `trading-gateway/` service (documented, independently
deployed, asserted unused by tests), historical docs, and generated `changes.patch` /
`check_*.ts` helpers, which remain under the repository's decision rather than this audit's.

## 5. Design benchmark: what the leaders do, and where we stand

Reviewed first-hand documentation for TradingView Supercharts, Coinbase Advanced and
Kraken Pro. The three of them converge on the same handful of principles.

| Principle the leaders share | Our state before | Change made |
|---|---|---|
| Chart is the centre of gravity; chrome stays contextual | Chart competed with a large account-integration panel directly beneath the metrics | Overview now reads header → readiness → metrics → chart+signal → positions/risk/activity; the integration ledger moved to the bottom, where it belongs |
| One obvious answer to "what is the state of my account?" | Equity was labelled "COINDCX FUTURES" even in simulated mode; error states left plausible stale numbers | Explicit "SIMULATED ACCOUNT · NOT REAL FUNDS" / "EXCHANGE WALLET" labels, and a visible retry banner when a refresh fails |
| Answer "what do I do next?" without hunting | Nine pages, dense uppercase labels, no onboarding into the product's logic | New **Decision readiness** strip: data source, analysis freshness, setup candidate and execution mode, each with its next action |
| Typographic discipline, restrained low-chrome palette | 10px labels at 0.14em tracking, decorative grid background, card-lift hover, duplicate `.panel` rules | Slightly larger label tracking, flat workspace background, static surfaces, single consolidated panel definition, softer border/contrast tokens |
| Dense data needs breathing room and scannable hierarchy | 12px page padding, 12px metric values, three-column mini layouts | 16/24px page rhythm, 23px metric values, page headers with breadcrumbs on the main routes, 44px toolbar |
| Deterministic, honest provenance | Demo/live/ticker labels disagreed across panels | Consistent "DEMO DATA" / "SIMULATED" wording, per-panel source chips, and an explicit note that signals are research candidates |
| Accessibility is part of "professional" | No skip link, small tap targets, motion settings existed but reduced-motion was undetected | Skip link, 24px touch minimums on coarse pointers, `prefers-reduced-motion` support in addition to the manual toggle, preserved focus rings |

What the leaders have that this project **already** has: a command palette and keyboard
map, saved module visibility, watchlists, alerts with browser/audio delivery, an order
ticket separated from analysis, order book with depth bars, paper trading, a trade journal,
performance analytics, multi-timeframe charting with drawings, and a documented
read-only → paper → live trust progression. Those overlap areas were left alone rather
than reinvented.

The "bad" patterns named in the brief are **not** wholesale defects of those products; they
are the compromises that show up in almost every trading terminal — dense toolbars, settings
buried three levels deep, decorative gradients, and statistics that look more authoritative
than they are. Where this project had its own version of those problems (cosmetic depth,
misleading ratio labels, buried mode controls), it was fixed rather than copied.

## 6. What the popular projects have that we deliberately did not add

- **News, social feeds, ideas and sentiment**: needs licensed content and moderation, and is
  a distraction in a single-account personal terminal.
- **Server-side strategy marketplace / copy trading**: not meaningful for one account, and
  adds a trust surface we cannot verify.
- **Native desktop/mobile applications**: the responsive web workspace is the product here.
- **More indicators for their own sake**: TradingView's own guidance is to add tools that
  answer a question. Our four features answer a question; a fifth should be justified by
  evidence, not by parity.

## 7. Unique direction: evidence-first, not prediction-first

Positioning that the mainstream tools do not occupy: every recommendation-shaped surface
must show the evidence behind it, and the application must be able to *disprove* its own
signal. First delivery is in the product today (the readiness strip). The honest roadmap,
in order:

1. **Decision snapshots** — persist, per candidate signal: candle data hash, config, engine
   version, timestamp, and what happened afterwards. Immutable, replayable, auditable.
2. **Out-of-sample validation with uncertainty** — block-bootstrapped confidence intervals
   on expectancy, profit factor and drawdown, per market and per regime, replacing single
   point estimates.
3. **Portfolio-level risk** — correlation clustering and simultaneous-exposure limits
   instead of per-symbol limits; fee and funding stress scenarios on open positions.
4. **Replay → paper → live promotion gates** — a strategy may only reach paper after
   recorded out-of-sample evidence, and live only after a recorded paper period with the
   same configuration.
5. **Signal provenance ledger UI** — a page where each historical signal lists its inputs and
   outcome, so the operator can judge the process rather than the last screenshot.

These are deliberately gated on data reliability: sizing depends on a verifiable equity
figure, and a live daily-loss limit that cannot be proven is treated as unknown, not zero.

## 8b. Follow-up delivered after this audit

Two deeper deliverables were added in response to the design and competitiveness questions:

- `docs/DESIGN_BENCHMARK.md` — goods **and** bads collected from eight leading products, with an
  explicit audit of which anti-patterns this project already contained (density control that did
  nothing, colour-only semantics, decorative depth, unlabelled statistics, tiny tap targets,
  unbounded alerting) and what changed for each. New implementations: watchlist rail beside the
  chart, inline plain-language glossary (30+ terms), colour-vision-safe palette with direction
  glyphs, working compact density.
- `docs/FUTURE_ROADMAP.md` — gap analysis against charting, exchange, order-flow, journal,
  automation, DeFi and institutional categories, plus a ranked roadmap of unique, evidence-first
  capabilities with honest data dependencies.

Also implemented from that roadmap's "now" list: the **signal accountability ledger** —
`src/lib/strategy/v2/outcomes.ts`, `GET /api/signals/outcomes` and the
`SignalAccountability` panel on `/strategy`, which scores every recorded setup's published plan
(target hit / stop hit / still open / not evaluated with a reason, MFE and MAE in R) and refuses
to score malformed plans instead of counting them as wins.

## 9. Known limitations and residual risk

- **No profitability evidence.** Backtests use exchange candles plus estimated fee/slippage
  assumptions; funding, partial fills and latency are not modelled. The regression suite
  asserts mechanism, not edge.
- **Live execution remains disabled by default** with two independent gates. Nothing in this
  audit changes that posture, and it should not be enabled on the strength of these tests.
- **Dependency advisories.** `npm audit` reports high/moderate advisories in the
  `eslint-config-next` and `drizzle-kit` tool chains (transitive `braces`, `micromatch`,
  `esbuild`). All are development-only, none ship in the server bundle, and the available
  fixes are semver-major tooling upgrades; they are documented rather than force-upgraded in
  this pass.
- **Fonts are self-hosted now** (`@fontsource-variable/inter`,
  `@fontsource-variable/jetbrains-mono`) instead of downloaded by `next/font/google`, so
  builds no longer depend on reaching Google Fonts and the network-font privacy note in the
  original comment was corrected.
- **Chart tick formatting locale is pinned** (`en-US`). Browsers that report a non-BCP-47
  `navigator.language` (for example `en-US@posix`) previously threw inside the chart's tick
  formatter, which blanked the chart body; the fix removes that failure mode for every
  chart instance.
- **Demo data is synthetic.** The simulator is deterministic and clearly labelled; it is not
  a market model and must not be used to judge strategy quality.
